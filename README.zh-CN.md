# 文脉大模型 VanMach-7B

### 文档语言

[**英语**](./README.md) | [**简体中文**](./README.zh-CN.md) | [**繁体中文**](./README.zh-TW.md) | [**越南语**](./README.vi.md)

## 1. 模型简介

**文脉大模型（越南语：Văn Mạch；英语：Van Mach，模型编号：VanMach-7B）** 是一款面向越南传统文字（喃字）、历史文献与语言文化领域的 7B 量级多语言大语言模型。模型以 [SeaLLMs-v3-7B-Chat](https://huggingface.co/SeaLLMs/SeaLLMs-v3-7B-Chat) 为基座，通过专门设计的喃字词表扩展、纯数学计算的词嵌入初始化、增量预训练（CPT）以及指令监督微调（SFT）等步骤，增强模型对越南喃字（Chữ Nôm）、现代越南语、汉喃历史文献及越南传统文化知识的处理能力。不同于主要针对现代越南语自然语言处理任务的通用模型，我们的 VanMach-7B 将 **喃字的语言学计算表示、历史语言知识与现代越南语之间的关联** 作为模型开发的核心方向。模型支持以下三种语言及其相应书写形式： **越南语** 【国语字（Chữ Quốc ngữ）以及历史上使用的喃字（Chữ Nôm）】、**中文** 【简体中文与繁体中文】、**英语**。

喃字是越南历史上用于书写越南语的重要文字系统，其字形与汉字体系具有密切联系，但在字义、读音、字形构成以及实际用法方面又具有自身的特点。大量喃字在现代通用大模型的训练语料中出现频率极低，部分字符甚至无法通过已有分词器获得独立、完整的 Token 表示。与此同时，喃字可利用的数字化训练语料相对有限，尤其缺少大规模、经过系统整理的高质量现代语对齐数据。这使得传统的大模型微调方法面临较为突出的挑战：

1. **文字表示不足**：大量喃字缺少独立 Token，容易被拆分为多个子词或字节级 Token，难以直接形成稳定的单字语义表示。
2. **训练数据稀缺**：汉喃文献及喃字辞书具有重要的语言学和历史价值，但可直接用于大模型训练的规模相对有限。
3. **随机初始化收敛缓慢**：如果直接为新增喃字随机初始化词嵌入，则模型需要在有限语料中同时学习文字的基本表示、读音关联和上下文语义。
4. **跨文字系统对齐困难**：喃字、汉字以及现代越南语国语字之间具有复杂的历史和语言关系，难以仅依赖普通文本训练充分建立联系。
5. **计算资源受限**：大规模词表扩展与持续训练通常需要额外显存及计算开销，对单卡环境尤其不利。

针对上述问题，VanMach-7B 采用了一条不同于单纯随机初始化与直接微调的技术路线：

**首先通过辞书知识、已有汉字向量、越南语读音表示与凸优化方法，在训练开始前为新增喃字构造具有语言学依据的初始表示（注入单字的词嵌入），随后通过CPT与SFT逐步学习喃字的实际用法、现代越南语对应关系以及相关文化知识。**

## 3. 训练语料与知识来源

VanMach-7B 的训练语料重点覆盖越南传统文字、历史文学、汉喃辞书、文字识别数据以及现代越南语词汇知识。与仅依靠大规模网络文本训练的通用语言模型不同，本项目充分利用具有明确语言学结构的辞书和文字资料，将其用于词嵌入初始化、增量预训练和指令监督微调。

#### Tự Điển Chữ Nôm Dẫn Giải

《Tự Điển Chữ Nôm Dẫn Giải》（喃字释义辞典）是本项目的重要喃字语言知识来源之一。这类资料包含喃字及其相关读音、释义和文字信息，对于建立喃字与现代越南语之间的联系具有重要价值。在模型开发中，辞书性质的数据主要用于建立喃字与越南语国语字读音之间的对应关系、为新扩展的喃字 Token 构建数学初始化所需的语言知识，以及构造结构化训练文本。

#### 越南汉喃复兴委员会喃字标准表

项目还使用了由 **Ủy ban Phục sinh Hán Nôm Việt Nam（越南汉喃复兴委员会）** 发布的喃字标准表。相关资源用于补充和整理喃字字符信息，为字符覆盖、词表扩展及文字标准化处理提供参考。

#### Hugging Face 汉喃与汉越音数据集

此外，训练还使用了 Hugging Face 平台上的若干汉喃数据集及汉越音数据集，这些数据用于补充喃字、汉字、汉越音与越南语之间的文字和语音关联。

#### 古代越南文学

为了使模型能够接触真实历史语境中的语言形式，VanMach-7B 引入了多部越南古典文学作品。

主要包括：

| 语料 | 内容与训练价值 |

| 《金云翘传》（Truyện Kiều） | 越南古典文学中的代表性作品，用于构造国语字-喃字平行语料、补充古代越南语表达和文学词汇 |
| 《征妇吟》（Chinh phụ ngâm） | 用于学习古典文学语言、诗歌表达及相关文化知识 |

| 《大越史记》 | 用于补充越南历史、传统制度、人物、地名、历史事件以及相关文言与汉喃书写形式。 |

#### OCR 文本数据

项目使用了 **NomNaOCR** 发布的文本数据。

## 4. 模型训练

VanMach-7B 的训练分为三个阶段：首先利用喃字辞书、原始模型的词嵌入空间和凸优化方法，为新增的 13,612 个喃字 Token 初始化输入词嵌入及 LM Head 权重。随后通过增量预训练（CPT），结合汉喃文献、现代越南语及结构化辞书语料，进一步训练新增喃字和相关汉字的表示，并注入领域语言与文化知识。最后采用指令监督微调（SFT），利用平行语料及结构化问答数据强化模型对喃字、汉喃文献和越南语言文化知识的理解与指令响应能力。

### 4.1 新增喃字词嵌入初始化方法

由于原始模型对大量喃字缺乏独立的 Token 表示，而汉喃文献的可用训练语料和计算资源均较为有限，直接采用随机初始化难以充分利用已有的语言学知识。本项目因此设计了一套基于辞书映射、字形转换与凸优化的词嵌入初始化算法，在正式梯度训练之前，为新增喃字构造具有语言学依据的初始表示。设原始模型的词表大小为 \(V_0=152064\) ，词嵌入维度为 \(d=3584\) ，输入词嵌入矩阵与语言模型输出权重矩阵分别记为 \(E,W\in\mathbb{R}^{V_0\times d}\) 。对于原始分词器中的任意 Token ID \(t\) ，以 \(E_t\) 和 \(W_t\) 分别表示两个矩阵中对应的行向量。算法分别在输入与输出参数空间中构造新增字符的初始向量。

**字符识别与直接映射。** 首先读取喃字—国语字读音字典，对字符和读音进行 Unicode NFC 规范化、大小写及空白归一化，并合并重复读音。随后使用原始分词器识别已知字符：仅当某字符能够被编码为一个非特殊 Token，且解码结果与原始字符完全一致时，才认为其具有有效的独立表示。对于尚未被独立编码的喃字，优先通过 OpenCC 的 `t2s` 规则进行字形转换；若转换结果为不同的单字符，且已存在独立 Token，则分别复制该字符在输入词嵌入矩阵和 LM Head 中的权重。其余字符进入基于读音的数学初始化流程。

**读音表示与参考锚点。** 为利用已有字符与现代越南语读音之间的对应关系，算法首先根据字典构建读音参考集合。具体而言，将字典中具有相同国语字读音的已知字符归为一组，并以每一种有效读音及其对应的已知字符集合建立一组参考向量。设 \(q\) 表示某一国语字读音， \(T(q)=(t_1,\ldots,t_m)\) 为原始分词器对该读音编码得到的 Token ID 序列，其中 \(m=|T(q)|\) 为序列长度； \(H(q)\) 为字典中具有该读音、且能够被原始分词器独立编码的已知字符所对应的 Token ID 集合。对于 \(T(q)\) 有效且 \(H(q)\) 非空的读音，定义：

$$
v_q=\frac{1}{|T(q)|}\sum_{t\in T(q)}E_t,\qquad
C_q=\frac{1}{|H(q)|}\sum_{h\in H(q)}E_h,\qquad
U_q=\frac{1}{|H(q)|}\sum_{h\in H(q)}W_h
$$

其中， \(v_q\) 表示国语字读音在原始词嵌入空间中的位置， \(C_q\) 和 \(U_q\) 分别表示同音已知字符的输入嵌入中心和 LM Head 权重中心。由此，每一种有效读音均对应一个由 \((v_q,C_q,U_q)\) 构成的三元参考关系，称为 **读音锚点** 。读音锚点以国语字读音为索引，通过字典中的字音对应关系，将读音的向量表示与已有字符的输入、输出参数联系起来。读音向量通过对原始分词结果取嵌入均值获得，不额外训练编码器；对于包含未知 Token 或特殊 Token、无法有效编码的读音，则不构建有效读音锚点。参考字符严格限定为字典中已被原始分词器独立编码的字符，不直接使用整个 Unicode 汉字区或原始词表中的全部汉字作为锚点。

**凸优化与向量迁移。** 对于无法直接建立同音字符参考中心、但能够通过原始分词器计算读音向量的目标读音，算法将其表示问题转化为读音向量在已有读音锚点凸包上的投影问题。设读音参考集合包含 \(n\) 个有效锚点，其对应的国语字读音依次为 \(q_1,q_2,\ldots,q_n\) ，并简记各锚点的三个向量为 \(v_i=v_{q_i}\) 、 \(C_i=C_{q_i}\) 和 \(U_i=U_{q_i}\) 。对于未包含在该参考集合中的目标读音 \(q\) ，首先按照前述方法计算其读音向量 \(v_q\) ，然后寻找一组组合系数 \(\boldsymbol{\alpha}=(\alpha_1,\ldots,\alpha_n)\) ，使参考读音向量的加权和与目标读音向量之间的欧氏距离最小：

$$
\boldsymbol{\alpha}^{*}
=\arg\min_{\boldsymbol{\alpha}}
\frac{1}{2}\left\|
\sum_{i=1}^{n}\alpha_i v_i-v_q
\right\|_2^2,
\qquad
\alpha_i\geq0,\quad
\sum_{i=1}^{n}\alpha_i=1
$$

其中， \(\alpha_i\) 表示第 \(i\) 个读音锚点的组合权重， \(\boldsymbol{\alpha}^{*}\) 表示满足约束条件的最优系数向量， \(\|\cdot\|_2\) 表示欧氏范数。该问题是具有概率单纯形约束的凸二次优化问题，其目标是在已有读音参考向量构成的凸包中寻找最接近目标读音的位置。求解后，算法并不直接以凸投影向量作为字符嵌入，而是将得到的组合系数分别应用于对应读音锚点的输入、输出参考中心：

$$
\widehat E_q=\sum_{i=1}^{n}\alpha_i^{*}C_i,
\qquad
\widehat W_q=\sum_{i=1}^{n}\alpha_i^{*}U_i
$$

其中， \(\widehat E_q\) 和 \(\widehat W_q\) 分别表示根据目标读音 \(q\) 构造的输入嵌入参考向量和 LM Head 权重参考向量。因此，国语字读音向量负责确定不同参考锚点之间的组合关系，而已有字符的输入嵌入与 LM Head 权重则用于构造实际的初始化参数。这使算法能够利用原始模型已有的越南语读音表示和汉字、喃字参数信息，而不是将所有新增字符置于随机位置。

**数值求解与收敛控制。** 实际实现采用 Frank–Wolfe 型条件梯度迭代，以当前投影残差为依据选择参考顶点，并通过约束在 \([0,1]\) 区间内的解析线搜索更新凸组合。算法不构造完整的大规模锚点 Gram 矩阵，而是利用 GPU 执行 FP64 向量内积与矩阵运算，并对活动参考集合定期使用 SLSQP 进行局部修正。参考向量按照其范数中位数进行尺度归一化，默认最大迭代次数为 1,800，最优性容差为 \(2\times10^{-8}\) ，同时依据 Frank–Wolfe 间隙判断主优化的数值收敛情况。

考虑到不同凸组合可能产生相同的投影向量，算法在主优化满足收敛条件后进一步尝试最小范数优化。设主优化得到的投影位置为 \(p^{*}=\sum_{i=1}^{n}\alpha_i^{*}v_i\) ，则在保持该投影位置不变的条件下，进一步求解：

$$
\min_{\boldsymbol{\alpha}}
\frac{1}{2}\|\boldsymbol{\alpha}\|_2^2,
\qquad
\sum_{i=1}^{n}\alpha_i v_i=p^{*},\quad
\sum_{i=1}^{n}\alpha_i=1,\quad
\alpha_i\geq0
$$

该次级优化旨在从对应同一投影位置的可行系数组合中选择欧氏范数较小的解；若其通过数值验证，则使用修正后的系数进行前述输入和输出参考向量的构造。次级优化结合奇异值分解（SVD）、SLSQP、L-BFGS-B 对偶优化及 Karush–Kuhn–Tucker（KKT）最优性条件检查，在保持投影位置与凸组合约束的前提下尝试获得稳定的系数解。对于未达到完整收敛或数值验证未通过的情况，程序保留已经找到的较优可行组合，并记录相应状态，避免因局部数值求解失败而直接丢失字符的初始化结果。

**多读音处理与回退机制。** 对于具有多个国语字读音的喃字，算法分别构造每个读音对应的输入与输出参考向量，再对各读音结果取算术平均，得到该字符的初始参数。具体而言，设 \(c\) 为待初始化的喃字， \(R(c)\) 为字典中记录的该字符的不同国语字读音集合， \(e_c^{(0)}\) 和 \(w_c^{(0)}\) 分别为该字符最终得到的输入词嵌入与 LM Head 初始向量，则对于采用读音初始化的字符，有：

$$
e_c^{(0)}=\frac{1}{|R(c)|}\sum_{q\in R(c)}\widehat E_q,
\qquad
w_c^{(0)}=\frac{1}{|R(c)|}\sum_{q\in R(c)}\widehat W_q
$$

其中，对于能够在读音参考集合中直接匹配的读音， \(\widehat E_q\) 与 \(\widehat W_q\) 直接取其对应的 \(C_q\) 和 \(U_q\) ；对于未直接匹配但可有效编码的读音，则使用凸优化构造的结果。若个别读音无法有效编码、缺少可用参考锚点或无法建立有效的优化问题，则以字典中全部已知字符的平均输入嵌入及平均 LM Head 权重作为该读音的回退向量；其他读音已有的有效结果仍予保留并参与最终平均。因此，算法的回退处理发生在读音层面，而不会因为某一读音缺失就放弃整个字符的已知信息。

**重复向量区分。** 对于具有相同读音组合或参考关系的新增字符（ **异体喃字** ），初始化可能得到相同的向量。为减少这种情况，程序分别检查输入嵌入与 LM Head 在实际存储精度下的向量表示，并在需要时进行最小有效扰动。具体方法是从高斯分布中随机采样单位方向，根据 FP16、BF16 或 FP32 等实际权重格式的相邻可表示数与舍入边界，计算能够产生有效数值变化的近似最小步长，再通过二分搜索进一步缩小扰动幅度；必要时采用单个坐标的一 ULP（Unit in the Last Place，即末位单位）调整作为回退方案。该过程以尽可能保留原始初始化向量为原则，直接字形映射的合法向量复制关系予以保留。

这一阶段完全基于既有权重、字典知识和数值计算完成，不进行训练。其主要作用是将已有汉字、喃字和现代越南语的表示关系转化为新增字符的初始参数，使后续 CPT 能够从具有语言学依据的向量出发，进一步通过实际上下文学习字符的读音、用法与语义。

### 4.2 增量预训练（CPT）

CPT 阶段以汉喃文字表示学习、越南语语言建模及领域知识注入为主要目标。训练语料包括《金云翘传》《征妇吟》《蓼云仙》《大越史记》《胡春香诗集》等文学与历史资料、NomNaOCR 文本数据，以及喃字辞书、喃字标准表、汉越音数据集和现代越南语词典。对于文学作品、历史文献等连续文本，直接进行自回归语言模型训练；对于辞书、读音表和其他结构化资料，则按照预定义模板转换为连续文本，以建立喃字字符、国语字读音、汉越音、释义及上下文之间的联系。

本阶段采用 QLoRA 算法，基础模型权重使用 NF4 四位量化，LoRA 秩设为 \(r=64\) ，文本截断长度为 1,024 Token。与仅训练低秩适配器的常规方法不同，CPT 阶段还解除相关字符嵌入及 LM Head 的冻结状态，使简体汉字、繁体汉字和喃字等相关单字词嵌入能够显式接受梯度更新，同时也允许 LM Head 参与训练。这样既可以继续修正第一阶段由数学方法初始化的新增喃字向量，也能够调整同时为喃字的汉字其嵌入向量。

### 4.3 指令监督微调（SFT）

SFT 阶段主要利用平行语料和辞书等结构化数据构建监督问答样本，以强化模型对喃字读音、释义、汉越音、国语字对应关系及越南历史文化知识的调用能力，并进一步训练其对汉喃文本解释和跨语言指令的响应。训练采用 LoRA 算法，以 FP8 精度进行微调，秩设为 \(r=32\) ，文本截断长度为 1,536 Token。

与 CPT 阶段不同，SFT 阶段冻结输入词嵌入层和 LM Head，仅通过低秩适配器进行参数更新。这一设置使模型在保留前两个阶段已形成的字符表示基础上，将训练重点转向结构化知识问答、指令理解及回答生成。

|  | 算法 | 秩 | 量化精度 | 截断长度 |
| --- | --- | --- | --- | --- |
| CPT | QLoRA | 64 | NF4 | 1,024 |
| SFT | LoRA | 32 | FP8 | 1,536 |

### 4.4 软硬件环境

VanMach-7B 使用单张 NVIDIA GeForce RTX 5060 Ti 16GB 显卡完成微调，训练框架为 Axolotl v0.20.0。CPT 与 SFT 分别使用 QLoRA 和 LoRA，以适应单卡 16GB 显存的计算资源限制。

## 5. 使用示例

VanMach-7B 基于 Hugging Face Transformers 生态，可使用标准的自回归语言模型加载方式。

```python
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

path = "./VanMach-7B"
tokenizer = AutoTokenizer.from_pretrained(path)
model = AutoModelForCausalLM.from_pretrained(
    path, torch_dtype=torch.bfloat16, device_map="cuda"
)
messages = []

while True:
    question = input("User: ")
    messages.append({"role": "user", "content": question})
    inputs = tokenizer.apply_chat_template(
        messages, add_generation_prompt=True, return_tensors="pt"
    ).to(model.device)
    outputs = model.generate(inputs, max_new_tokens=512)
    answer = tokenizer.decode(
        outputs[0][inputs.shape[-1]:], skip_special_tokens=True
    )
    print("Assistant:", answer)
    messages.append({"role": "assistant", "content": answer})
```
