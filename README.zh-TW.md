# 文脈大模型 VanMach-7B

### 文件語言

[**英語**](./README.md) | [**簡體中文**](./README.zh-CN.md) | [**繁體中文**](./README.zh-TW.md) | [**越南語**](./README.vi.md)

## 1. 模型簡介

**文脈大模型（越南語：Văn Mạch；英語：Van Mach，模型編號：VanMach-7B）** 是一款面向越南傳統文字（喃字）、歷史文獻與語言文化領域的 7B 規模多語言大型語言模型。模型以 [SeaLLMs-v3-7B-Chat](https://huggingface.co/SeaLLMs/SeaLLMs-v3-7B-Chat) 為基礎模型，透過專門設計的喃字詞彙表擴充、純數學計算的詞嵌入初始化、增量預訓練（CPT）以及指令監督微調（SFT）等步驟，增強模型對越南喃字（Chữ Nôm）、現代越南語、漢喃歷史文獻及越南傳統文化知識的處理能力。不同於主要針對現代越南語自然語言處理任務的通用模型，我們的 VanMach-7B 將 **喃字的語言學計算表示、歷史語言知識與現代越南語之間的關聯** 作為模型開發的核心方向。模型支援以下三種語言及其相應書寫形式： **越南語** 【國語字（Chữ Quốc ngữ）以及歷史上使用的喃字（Chữ Nôm）】、**中文** 【簡體中文與繁體中文】、**英語**。

喃字是越南歷史上用於書寫越南語的重要文字系統，其字形與漢字體系具有密切關聯，但在字義、讀音、字形構成以及實際用法方面又具有自身的特點。大量喃字在現代通用大型語言模型的訓練語料中出現頻率極低，部分字元甚至無法透過既有分詞器獲得獨立、完整的 Token 表示。與此同時，喃字可利用的數位化訓練語料相對有限，尤其缺乏大規模、經過系統整理的高品質現代語對齊資料。這使得傳統的大型語言模型微調方法面臨較為突出的挑戰：

1. **文字表示不足**：大量喃字缺乏獨立 Token，容易被拆分為多個子詞或位元組級 Token，難以直接形成穩定的單字語意表示。
2. **訓練資料稀缺**：漢喃文獻及喃字辭書具有重要的語言學和歷史價值，但可直接用於大型語言模型訓練的規模相對有限。
3. **隨機初始化收斂緩慢**：如果直接為新增喃字隨機初始化詞嵌入，則模型需要在有限語料中同時學習文字的基本表示、讀音關聯和上下文語意。
4. **跨文字系統對齊困難**：喃字、漢字以及現代越南語國語字之間具有複雜的歷史和語言關係，難以僅依賴一般文字訓練充分建立關聯。
5. **運算資源受限**：大規模詞彙表擴充與持續訓練通常需要額外的顯示記憶體及運算開銷，對單張顯示卡環境尤其不利。

針對上述問題，VanMach-7B 採用了一條不同於單純隨機初始化與直接微調的技術路線：

**首先透過辭書知識、既有漢字向量、越南語讀音表示與凸最佳化方法，在訓練開始前為新增喃字建構具有語言學依據的初始表示（注入單字的詞嵌入），隨後透過CPT與SFT逐步學習喃字的實際用法、現代越南語對應關係以及相關文化知識。**

## 3. 訓練語料與知識來源

#### Tự Điển Chữ Nôm Dẫn Giải

《Tự Điển Chữ Nôm Dẫn Giải》（喃字釋義辭典）是本專案的重要喃字語言知識來源之一。這類資料包含喃字及其相關讀音、釋義和文字資訊，對於建立喃字與現代越南語之間的關聯具有重要價值。在模型開發中，辭書性質的資料主要用於建立喃字與越南語國語字讀音之間的對應關係、為新擴充的喃字 Token 建構數學初始化所需的語言知識，以及建構結構化訓練文字。

#### 越南漢喃復興委員會喃字標準表

專案還使用了由 **Ủy ban Phục sinh Hán Nôm Việt Nam（越南漢喃復興委員會）** 發布的喃字標準表。相關資源用於補充和整理喃字字元資訊，為字元涵蓋範圍、詞彙表擴充及文字標準化處理提供參考。

#### Hugging Face 漢喃與漢越音資料集

## 4. 模型訓練

VanMach-7B 的訓練分為三個階段：首先利用喃字辭書、原始模型的詞嵌入空間和凸最佳化方法，為新增的 13,612 個喃字 Token 初始化輸入詞嵌入及 LM Head 權重。隨後透過增量預訓練（CPT），結合漢喃文獻、現代越南語及結構化辭書語料，進一步訓練新增喃字和相關漢字的表示，並注入領域語言與文化知識。最後採用指令監督微調（SFT），利用平行語料及結構化問答資料強化模型對喃字、漢喃文獻和越南語言文化知識的理解與指令回應能力。

### 4.1 新增喃字詞嵌入初始化方法

由於原始模型對大量喃字缺乏獨立的 Token 表示，而漢喃文獻的可用訓練語料和運算資源均較為有限，直接採用隨機初始化難以充分利用既有的語言學知識。本專案因此設計了一套基於辭書映射、字形轉換與凸最佳化的詞嵌入初始化演算法，在正式梯度訓練之前，為新增喃字建構具有語言學依據的初始表示。設原始模型的詞彙表大小為 \(V_0=152064\) ，詞嵌入維度為 \(d=3584\) ，輸入詞嵌入矩陣與語言模型輸出權重矩陣分別記為 \(E,W\in\mathbb{R}^{V_0\times d}\) 。對於原始分詞器中的任意 Token ID \(t\) ，以 \(E_t\) 和 \(W_t\) 分別表示兩個矩陣中對應的列向量。演算法分別在輸入與輸出參數空間中建構新增字元的初始向量。

**字元辨識與直接映射。** 首先讀取喃字—國語字讀音字典，對字元和讀音進行 Unicode NFC 正規化、大小寫及空白正規化，並合併重複讀音。隨後使用原始分詞器辨識已知字元：僅當某字元能夠被編碼為一個非特殊 Token，且解碼結果與原始字元完全一致時，才認為其具有有效的獨立表示。對於尚未被獨立編碼的喃字，優先透過 OpenCC 的 `t2s` 規則進行字形轉換；若轉換結果為不同的單一字元，且已存在獨立 Token，則分別複製該字元在輸入詞嵌入矩陣和 LM Head 中的權重。其餘字元進入基於讀音的數學初始化流程。

**讀音表示與參考錨點。** 為利用既有字元與現代越南語讀音之間的對應關係，演算法首先根據字典建構讀音參考集合。具體而言，將字典中具有相同國語字讀音的已知字元歸為一組，並以每一種有效讀音及其對應的已知字元集合建立一組參考向量。設 \(q\) 表示某一國語字讀音， \(T(q)=(t_1,\ldots,t_m)\) 為原始分詞器對該讀音編碼得到的 Token ID 序列，其中 \(m=|T(q)|\) 為序列長度； \(H(q)\) 為字典中具有該讀音、且能夠被原始分詞器獨立編碼的已知字元所對應的 Token ID 集合。對於 \(T(q)\) 有效且 \(H(q)\) 非空的讀音，定義：

$$
v_q=\frac{1}{|T(q)|}\sum_{t\in T(q)}E_t,\qquad
C_q=\frac{1}{|H(q)|}\sum_{h\in H(q)}E_h,\qquad
U_q=\frac{1}{|H(q)|}\sum_{h\in H(q)}W_h
$$

其中， \(v_q\) 表示國語字讀音在原始詞嵌入空間中的位置， \(C_q\) 和 \(U_q\) 分別表示同音已知字元的輸入嵌入中心和 LM Head 權重中心。由此，每一種有效讀音均對應一個由 \((v_q,C_q,U_q)\) 構成的三元參考關係，稱為 **讀音錨點** 。讀音錨點以國語字讀音為索引，透過字典中的字音對應關係，將讀音的向量表示與既有字元的輸入、輸出參數聯繫起來。讀音向量透過對原始分詞結果取嵌入平均值獲得，不額外訓練編碼器；對於包含未知 Token 或特殊 Token、無法有效編碼的讀音，則不建構有效讀音錨點。參考字元嚴格限定為字典中已被原始分詞器獨立編碼的字元，不直接使用整個 Unicode 漢字區或原始詞彙表中的全部漢字作為錨點。

**凸最佳化與向量遷移。** 對於無法直接建立同音字元參考中心、但能夠透過原始分詞器計算讀音向量的目標讀音，演算法將其表示問題轉化為讀音向量在既有讀音錨點凸包上的投影問題。設讀音參考集合包含 \(n\) 個有效錨點，其對應的國語字讀音依序為 \(q_1,q_2,\ldots,q_n\) ，並簡記各錨點的三個向量為 \(v_i=v_{q_i}\) 、 \(C_i=C_{q_i}\) 和 \(U_i=U_{q_i}\) 。對於未包含在該參考集合中的目標讀音 \(q\) ，首先按照前述方法計算其讀音向量 \(v_q\) ，然後尋找一組組合係數 \(\boldsymbol{\alpha}=(\alpha_1,\ldots,\alpha_n)\) ，使參考讀音向量的加權和與目標讀音向量之間的歐氏距離最小：

$$
\boldsymbol{\alpha}^{*}
=\arg\min_{\boldsymbol{\alpha}}
\frac{1}{2}\left\|
\sum_{i=1}^{n}\alpha_i v_i-v_q
\right\|_2^2,
\qquad
\alpha_i\geq0,\quad
\sum_{i=1}^{n}\alpha_i=1
$$

其中， \(\alpha_i\) 表示第 \(i\) 個讀音錨點的組合權重， \(\boldsymbol{\alpha}^{*}\) 表示滿足約束條件的最優係數向量， \(\|\cdot\|_2\) 表示歐氏範數。該問題是具有機率單純形約束的凸二次最佳化問題，其目標是在既有讀音參考向量構成的凸包中尋找最接近目標讀音的位置。求解後，演算法並不直接以凸投影向量作為字元嵌入，而是將得到的組合係數分別應用於對應讀音錨點的輸入、輸出參考中心：

$$
\widehat E_q=\sum_{i=1}^{n}\alpha_i^{*}C_i,
\qquad
\widehat W_q=\sum_{i=1}^{n}\alpha_i^{*}U_i
$$

其中， \(\widehat E_q\) 和 \(\widehat W_q\) 分別表示根據目標讀音 \(q\) 建構的輸入嵌入參考向量和 LM Head 權重參考向量。因此，國語字讀音向量負責決定不同參考錨點之間的組合關係，而既有字元的輸入嵌入與 LM Head 權重則用於建構實際的初始化參數。這使演算法能夠利用原始模型既有的越南語讀音表示和漢字、喃字參數資訊，而不是將所有新增字元置於隨機位置。

**數值求解與收斂控制。** 實際實作採用 Frank–Wolfe 型條件梯度迭代，以目前投影殘差為依據選擇參考頂點，並透過約束在 \([0,1]\) 區間內的解析線搜尋更新凸組合。演算法不建構完整的大規模錨點 Gram 矩陣，而是利用 GPU 執行 FP64 向量內積與矩陣運算，並對作用中的參考集合定期使用 SLSQP 進行局部修正。參考向量按照其範數中位數進行尺度正規化，預設最大迭代次數為 1,800，最優性容差為 \(2\times10^{-8}\) ，同時依據 Frank–Wolfe 間隙判斷主要最佳化過程的數值收斂情況。

考慮到不同凸組合可能產生相同的投影向量，演算法在主要最佳化過程滿足收斂條件後進一步嘗試最小範數最佳化。設主要最佳化過程得到的投影位置為 \(p^{*}=\sum_{i=1}^{n}\alpha_i^{*}v_i\) ，則在保持該投影位置不變的條件下，進一步求解：

$$
\min_{\boldsymbol{\alpha}}
\frac{1}{2}\|\boldsymbol{\alpha}\|_2^2,
\qquad
\sum_{i=1}^{n}\alpha_i v_i=p^{*},\quad
\sum_{i=1}^{n}\alpha_i=1,\quad
\alpha_i\geq0
$$

該次級最佳化旨在從對應同一投影位置的可行係數組合中選擇歐氏範數較小的解；若其通過數值驗證，則使用修正後的係數進行前述輸入和輸出參考向量的建構。次級最佳化結合奇異值分解（SVD）、SLSQP、L-BFGS-B 對偶最佳化及 Karush–Kuhn–Tucker（KKT）最優性條件檢查，在保持投影位置與凸組合約束的前提下嘗試獲得穩定的係數解。對於未達到完整收斂或數值驗證未通過的情況，程式保留已經找到的較佳可行組合，並記錄相應狀態，避免因局部數值求解失敗而直接丟失字元的初始化結果。

**多讀音處理與回退機制。** 對於具有多個國語字讀音的喃字，演算法分別建構每個讀音對應的輸入與輸出參考向量，再對各讀音結果取算術平均值，得到該字元的初始參數。具體而言，設 \(c\) 為待初始化的喃字， \(R(c)\) 為字典中記錄的該字元的不同國語字讀音集合， \(e_c^{(0)}\) 和 \(w_c^{(0)}\) 分別為該字元最終得到的輸入詞嵌入與 LM Head 初始向量，則對於採用讀音初始化的字元，有：

$$
e_c^{(0)}=\frac{1}{|R(c)|}\sum_{q\in R(c)}\widehat E_q,
\qquad
w_c^{(0)}=\frac{1}{|R(c)|}\sum_{q\in R(c)}\widehat W_q
$$

其中，對於能夠在讀音參考集合中直接匹配的讀音， \(\widehat E_q\) 與 \(\widehat W_q\) 直接取其對應的 \(C_q\) 和 \(U_q\) ；對於未直接匹配但可有效編碼的讀音，則使用凸最佳化建構的結果。若個別讀音無法有效編碼、缺乏可用參考錨點或無法建立有效的最佳化問題，則以字典中全部已知字元的平均輸入嵌入及平均 LM Head 權重作為該讀音的回退向量；其他讀音已有的有效結果仍予保留並參與最終平均。因此，演算法的回退處理發生在讀音層面，而不會因為某一讀音缺失就放棄整個字元的已知資訊。

**重複向量區分。** 對於具有相同讀音組合或參考關係的新增字元（ **異體喃字** ），初始化可能得到相同的向量。為減少這種情況，程式分別檢查輸入嵌入與 LM Head 在實際儲存精度下的向量表示，並在需要時進行最小有效擾動。具體方法是從高斯分布中隨機取樣單位方向，根據 FP16、BF16 或 FP32 等實際權重格式的相鄰可表示數值與捨入邊界，計算能夠產生有效數值變化的近似最小步長，再透過二分搜尋進一步縮小擾動幅度；必要時採用單一座標的一 ULP（Unit in the Last Place，即末位單位）調整作為回退方案。該過程以盡可能保留原始初始化向量為原則，直接字形映射的合法向量複製關係予以保留。

這一階段完全基於既有權重、字典知識和數值計算完成，不進行訓練。其主要作用是將既有漢字、喃字和現代越南語的表示關係轉化為新增字元的初始參數，使後續 CPT 能夠從具有語言學依據的向量出發，進一步透過實際上下文學習字元的讀音、用法與語意。

### 4.2 增量預訓練（CPT）

CPT 階段以漢喃文字表示學習、越南語語言建模及領域知識注入為主要目標。訓練語料包括《金雲翹傳》《征婦吟》《蓼雲仙》《大越史記》《胡春香詩集》等文學與歷史資料、NomNaOCR 文字資料，以及喃字辭書、喃字標準表、漢越音資料集和現代越南語詞典。對於文學作品、歷史文獻等連續文字，直接進行自迴歸語言模型訓練；對於辭書、讀音表和其他結構化資料，則按照預先定義的範本轉換為連續文字，以建立喃字字元、國語字讀音、漢越音、釋義及上下文之間的關聯。

本階段採用 QLoRA 演算法，基礎模型權重使用 NF4 四位元量化，LoRA 秩設為 \(r=64\) ，文字截斷長度為 1,024 Token。與僅訓練低秩適配器的常規方法不同，CPT 階段還解除相關字元嵌入及 LM Head 的凍結狀態，使簡體漢字、繁體漢字和喃字等相關單字詞嵌入能夠明確接受梯度更新，同時也允許 LM Head 參與訓練。這樣既可以繼續修正第一階段由數學方法初始化的新增喃字向量，也能夠調整同時作為喃字的漢字之嵌入向量。

### 4.3 指令監督微調（SFT）

SFT 階段主要利用平行語料和辭書等結構化資料建構監督問答樣本，以強化模型對喃字讀音、釋義、漢越音、國語字對應關係及越南歷史文化知識的運用能力，並進一步訓練其對漢喃文字解釋和跨語言指令的回應。訓練採用 LoRA 演算法，以 FP8 精度進行微調，秩設為 \(r=32\) ，文字截斷長度為 1,536 Token。

與 CPT 階段不同，SFT 階段凍結輸入詞嵌入層和 LM Head，僅透過低秩適配器進行參數更新。這一設定使模型在保留前兩個階段已形成的字元表示基礎上，將訓練重點轉向結構化知識問答、指令理解及回答生成。

|  | 演算法 | 秩 | 量化精度 | 截斷長度 |
| --- | --- | --- | --- | --- |
| CPT | QLoRA | 64 | NF4 | 1,024 |
| SFT | LoRA | 32 | FP8 | 1,536 |

### 4.4 軟硬體環境

VanMach-7B 使用單張 NVIDIA GeForce RTX 5060 Ti 16GB 顯示卡完成微調，訓練框架為 Axolotl v0.20.0。CPT 與 SFT 分別使用 QLoRA 和 LoRA，以適應單張顯示卡 16GB 顯示記憶體的運算資源限制。

## 5. 使用範例

VanMach-7B 基於 Hugging Face Transformers 生態系統，可使用標準的自迴歸語言模型載入方式。

```python
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

path = "./VanMach-7B"
tokenizer = AutoTokenizer.from_pretrained(path)
model = AutoModelForCausalLM.from_pretrained(
    path, torch_dtype=torch.bfloat16, device_map="cuda"
)
messages = []

while True:
    question = input("User: ")
    messages.append({"role": "user", "content": question})
    inputs = tokenizer.apply_chat_template(
        messages, add_generation_prompt=True, return_tensors="pt"
    ).to(model.device)
    outputs = model.generate(inputs, max_new_tokens=512)
    answer = tokenizer.decode(
        outputs[0][inputs.shape[-1]:], skip_special_tokens=True
    )
    print("Assistant:", answer)
    messages.append({"role": "assistant", "content": answer})
```
